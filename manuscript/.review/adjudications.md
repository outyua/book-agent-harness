# 裁决记录

## 2026-08-20 · 源码用来讲课，不是核验

作者原话（终局，不标「待用户确认」）：「本书的重点不是要让用户去做各种认证核查，而是结合项目源码给用户讲清楚这个知识。」

### 结论

上一轮「三层引用」只对了一半：叙述句里的出处打断必须继续搬走；把读者定义成核对员、把 `file:line` 当成产品卖点，整段作废。

护城河是 23 个真实实现上的设计对照，不是「带 file:line 供读者核验」。源码是讲课材料：把真实实现摊开，讲选择、讲代价、讲抄哪一段。路径是题注和对照地图，不是作业。复核装置留给「版本与复核」和后记——给要复跑、要追论文的人，不是阅读主路径。

诚实边界不删软：厂商自述、未复现、通用 agent、样本有偏，仍要让人用对数字。那是讲课的一部分（100:1 别当成自己 coding agent 的账单），不是请他去做认证。

### 理由

1. **读者画像被写歪了。** 现行方针原文：「对照表和章末注里的 `file:line` 是给他用的；叙述句里的判断是让他先决定『要不要点进去核』。」目标读者是正在造 agent 的工程师，翻开书要搞懂自己系统里的岔口，不是被训练去核行号。
2. **样章已经按核对员写歪了。** 第 1 章 §1.1 表下「口径见注。[^1-4][^1-5][^1-6]」，四处「口径见注」把阅读停成认证手续。第 6 章 32 条章末注，几乎每句机制后面戳一个定位符；§6.2.1 代码已贴在页上、题注已有 `cache_semantics.rs:9-18`，叙述句还叠 `[^6-4]`。表 1-2 专开「证据级别」列，读表像盖章。
3. **定位卖点卖错了。** 「带 file:line 的源码横向对照」把作者取证链写成了读者义务。file:line 是作者取证与题注，不是这本书向读者承诺的东西。读者读完应当能面对岔口说出走法、代价、抄哪一段——这个承诺没变；兑现它靠讲课，不靠布置核验。
4. **诚实限定与核验作业不是同一件事。** 「厂商自述所以别当实测」改变读法，必须留在阅读主路径（叙述句后一句人话，或正文一句塞不下时的薄注）。「可以自己去核」「口径见注」「要不要点进去核」是把读者当核对员，禁止。

本裁决覆盖方针红线一、读者画像末句、定位与承诺里的护城河表述，以及 style sheet §4「叙述句必须带注号」。编辑方针已同步修订，见 `editorial-charter.md` 文首修订说明。

### 审稿校准（复审）

上一轮审稿按旧红线一验收，第 1、6 章第 2 轮都判达标——在「打断搬走」上成立，在「读者是不是核对员」上把关失败。偏差不是过松漏技术，是过严且方向错：把「注号不够多 / file:line 没进注 / 表下没有口径见注」当完成条件，等于把 P2 级的取证便利当成 P1 级的读者义务。

下一轮按新红线审，校准三条：

1. **把「注号不够多 / file:line 没进本章注」当 P1，属于过严，直接驳回。** 理由：那是把读者当核对员。页上有代码、表上有路径，叙述句叠定位符注号，应标 P1（打断阅读、布置核验）。
2. **「口径见注」「可以自己去核」「要不要点进去核」出现在叙述句或表下，标 P1。** 测量方法应在「版本与复核」，不在阅读主路径喊。
3. **诚实限定删软才是 P1。** 100:1 看不出厂商自述和通用 agent、未复现的数写得像自己系统的预期、上界写成实测——这是用错数字，不是核验不够。不要把「限定写进了叙述句、所以没戳注号」判成缺出处。

检验改成：读者能不能顺着机制读完；源码是不是在讲课而不是在布置核验。删掉所有注号之后，句子仍然完整、仍然下判断——这一条保留；加上一条：顺着读完全章，不必点开任何注，也能用对数字、决定抄不抄。
