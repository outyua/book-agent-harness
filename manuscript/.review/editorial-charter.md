## 读者画像

正在造或正在调一个 coding agent 的工程师。

- **职业背景**：有后端或工具链经验，能独立读 TypeScript / Python / Rust 源码，用过至少一家 LLM API（发过带工具调用的请求），手头已经有一个循环、或正在把 IDE 插件 / 内部 bot 收成可维护的系统。不是「听说过 agent 想了解一下」的人。
- **已具备**：知道模型会调工具、上下文有窗口上限、token 要花钱。不需要被科普什么是 LLM、什么是 prompt。
- **翻开这本书要解决的问题**：自己系统里每一个设计岔口——循环写成什么样、断点打几个、压缩何时做、权限判定放哪、要不要拆子 agent——别人是怎么选的、代价是什么、自己这种约束该抄哪一段。
- **明确排除**：要框架教程的人（本书不教 LangGraph）；要可复制咒语的人（第 7 章明说 prompt 措辞不可照抄）；要论文综述或产品评测的人（23 个项目不排名）。序里写了：如果你在找「AI agent 是什么」的入门材料，这本书不合适。

读的时候他对照的是自己系统里的岔口：未知组合该默认什么、循环能不能写成递归、断点打几个。源码出现在页上，是为了把机制摊开讲清楚——这段代码在哪，题注写路径；该抄哪一段、代价是什么，叙述句写判断。他不是被请来核行号的。要复跑、要追论文，去「版本与复核」和后记。

## 全书定位与承诺

这本书不复述框架，也不逐个介绍 23 个仓库。它对照同一个工程问题在 23 个真实 coding agent 中的不同实现，解释分歧原因、选择条件以及可以复用的部分（调研池 28 个，正文实际引用 23 个；5 个读过但没有用于正文）。`file:line` 是作者取证与代码题注，用于说明代码位置；论文和厂商文章用于支持具体结论，不承担章节组织功能。

读者读完应当能：面对自己 agent 里的任一设计岔口，说得出有哪几种走法、各自的失败模式、以及在他的约束下该选哪条。给不出「抄哪一段 / 不要抄哪一段」，这一章就还没写完。

证据是设计正确性证据，不是效果证据。诚实边界写在序里，不得写软：缺生产运营数据、缺国内第一方工程叙述、样本有偏（能拿到源码的才进池）、AHE 论文是单基准且本书未独立复现。这些信息保留，是为了读者用对数字（100:1 别当成自己 coding agent 的账单），不是为了请他去做认证。位置：序写一次；会改变读法的几个字（厂商自述、未复现、通用 agent、本书推算）跟数字走，写在叙述句；测量方法、复跑命令在「版本与复核」和后记。不要在每一句数字后面当场重读方法论，也不要喊「口径见注」。

17 章按一次 agent 运行的生命周期分成六个部，已经是完稿结构。不增删章节、不合并模块、不大范围重排。部的职责与阅读顺序维持如下：

## 内容红线与审读重点

给审稿人。每条带理由——靠理由泛化，不靠死记条文。

### 红线一：讲课优先。源码是讲课材料，不是核验作业。

这本书成立，是因为 23 个真实实现被摊开对照，读者能看懂选择和代价。把源码从全书抹掉，选题不成立。把每一句机制后面戳一个定位符注号、把读者训练成核行号的人，判断被挤没了，读感像认证手册。

| 位置 | 读者在做什么 | 放什么 | 不放什么 |
|---|---|---|---|
| 正文 | 搞懂机制，决定抄不抄 | 项目名、机制、判断、不成立的条件；需要时页上的代码；论文 / 文章短名；会改变读法的几个字（厂商自述、未复现、本书推算、通用 agent） | 完整 `path/file.ext:123`；上标串；「口径见注」；`[核 YYYY-MM-DD]`；URL；存档路径；底稿路径；作者全名 + 题名 + 年份 + arXiv 同时出现；「三点必须交代」「判定方法＝」；为戳注号而戳的定位符 |
| 代码题注 | 看这段代码在哪 | 路径与行号 | 核验口吻 |
| 对照表单元格 | 对照地图 | 路径、短哈希、日期 | 「证据级别」盖章列（级别用表后一句人话说清） |
| 本章注 | 偶尔查一条正文塞不下的限定 | 会改变用法的长限定；短名解不到后记 C 的书目补遗 | 1:1 回填的 `file:line`；新的判断；测量方法 / grep 口径 |
| 版本与复核 / 后记 | 要复跑、要追论文 | 测量命令、grep 口径、commit、完整书目 | 阅读主路径里的喊话 |

**上标。** 只在「出处身份会改变读法」时用：哪篇论文、哪篇博客、这个数是厂商自述所以别当实测——并且这句人话塞不进叙述句。短名已出、后记 C 能解、限定已经写在叙述句里的，不标。代码已在页上或表上，叙述句不再叠定位符注号。

**禁止。** 「口径见注」「可以自己去核」「要不要点进去核」；为戳注号而戳注号；表下用「口径见注」把读者打发到章末。

**本章注变薄。** 书目以短名解后记 C 为主。注只收会改变用法、正文一句塞不下的限定（通用 agent 不是 coding agent、未复现所以当方向不当精度、推算链长到会压垮判断）。不要 1:1 回填所有抽出的 `file:line`。测量方法、grep 口径进「版本与复核」。

检验两条，都要过：

1. 任意叙述句，删掉所有注号之后，句子仍然完整、仍然下判断。注号不是句子的语法成分。
2. 顺着读完全章，不必点开任何注，也能用对数字、决定抄不抄。限定写在叙述句里，不藏在注里当作业。

同一出处一章只建一条注，后文复用同一注号。多数出处根本不建注。

对照表单元格、代码块题注、验收清单里的 `file:line` **原样保留**。这些是讲课用具，不是打断，也不是核验作业。

### 红线二：抽出后只补机制与判断，禁止用总结句填空。

句子变短是预期。每抽出一处，改稿人问三句，答得上就写进正文，答不上就保持短：

1. **为什么这家这么做？**
2. **不这么做会怎样？**
3. **该抄哪一段、不要抄哪一段？**

禁止用「由此可见缓存很重要」「这再一次说明了 harness 的价值」这类句子把空洞填回去。删掉这句读者不损失任何东西，就删。已经补上的机制判断，本轮不要改回去。

正例（方案已给，改第 2 章时照此）：抽出「八个实现的主循环没有一个用递归」后面的普查口径之后，正文应写完——递归把恢复、熔断、插话的挂载点吃掉了，所以八家各自用 `while` 加状态对象。这不是风格偏好，是第 5 章、第 4 章能长在循环上的前提。普查口径进该章「版本与复核」，不要在段落后喊「口径见注」。

### 红线三：本轮只改样章。

第 1 章 + 第 6 章 + style sheet 冲突条。其余章、序、后记本轮不动。17 章骨架、五段结构职责顺序不动。改的是阅读主路径上的核验口吻和叠注号，不是章的骨架。

样章定的体例就是全书体例。力度按章的病型分，不要用同一刀切所有章：第 12、13、16、17 章以书目短名化为主、上标能省则省；第 2、6、7、14 章以叙述句去掉定位符注号、本章注删纯定位符为主。

### 红线四：诚实边界不得写软。

厂商自述、未复现、样本有偏、单基准、推算不是实测、通用 agent 不是 coding agent，全部保留。会改变读法的几个字写在叙述句（「厂商自述」「这是上界，不是实测」「通用 agent」）。禁止为了读起来干净，把「厂商自述」改成听上去像事实的句子。禁止把 E 级当 A 级用。禁止把限定藏进注、再请读者点开才知道这个数不能当自己的账单。

序里七条诚实边界是全书信用。同一条声明：序写一次，相关章的叙述句留几个字，够了。不要每出现一个数字就当场重读一遍方法论。

### 去 AI 味：真正要改的不是禁用词

禁用词表（赋能、抓手、众所周知、不难看出……）已经生效。更难发现的问题按伤害排序：

1. **核查口吻当正文。** 标志：口径注、三点必须交代、判定方法＝、承重位置、按这条口径、口径见注、可以自己去核、要不要点进去核、本书未独立复现（同一章重复多遍）。测量方法进「版本与复核」；会改变用法的限定用叙述句后一句普通人话写完。
2. **判断出口立刻自我拆台。** 标志：加粗短句 + 长括号把短句降级为推算 / 转述 / 未复现。改法：短句保留；限定条件用后一句普通陈述写完（「这是上界，不是实测」），细节进「版本与复核」或一条薄注。不要用括号把刚刚说的话再解释一遍。第 1 章 §1.1「剩下的 90% 以上就是本书要讲的东西」后面那个长括号，是这一条的标准病例。
3. **每章同构开场。** 「读完这一章，你能……」来自手册的五段纪律，不是模型随机生成，但读起来像模板。见上节局部调整 1。
4. **对仗与定义链过密。** 「不是 X 而是 Y」不禁用——纠正误读是本书的工作。只限制：**同一节内不要连用三组以上。** 「既不是 A 也不是 B，而是 C」同理。有把握就直接断言给依据；没把握写明不成立的边界，不靠对仗。
5. **证据限定被拆成标签。** 「本书测量。」「论文实测，未复现。」如果单独成句，读者无法确定它限定前一句、下一句还是整张表。把证据性质写进被限定的命题，例如「表 1-1 的行数和占比均为本书测量」。
6. **模糊指代代替对象。** 「那一行」「另一包」「那个数」在附近有多个候选对象时不成立。直接写表号、项目版本、路径或指标名，不让读者回头猜。
7. **编辑备注混入正文。** 「引用时会分开标」「后文会展开」描述的是作者接下来怎么写，不是读者现在需要知道的事实。当前段落直接说明差异；确需跳转时给准确章节号。
8. **口号、悬念和情绪判断代替推理。** 「剩下的就是本书要讲的东西」「合起来有个名字」「这不是巧合」「最重要的一条」都需要改成可核对的事实、因果或使用后果。没有证据证明因果时，只写观察结果和证据来源。
9. **隐喻省略执行过程。** 「吸附到切点」「日志没打通」「被噪声淹没」只有在上下文已经给出准确机制时才能保留；否则写成「向前查找最近的合法切点」「日志未被采集」「增加人工过滤无关结果的时间」。

术语先白话后名词、反面证据段、数字必须让人用对：这三条不是 AI 味，保留。出处不进叙述句；限定进叙述句。

### 本轮样章审读重点

### 标题层级

| 级 | Markdown | 承载什么 | 写法 |
|---|---|---|---|
| 章 | `#` | 一章一个 | `# 第 N 章 · {判断句或对象}`，与文件名标题一致 |
| 段 | `##` | 五段 + 本章注（可无）+ 版本与复核 | `## N.M {按内容拟定的标题}`。第 4 段显示名统一为「反面证据与失败模式」，第 5 段统一为「可抄的最小实现」。本章注不编号：`## 本章注`。版本与复核维持 `## N.6 版本与复核` |
| 节 | `###` | 段内可独立理解的一块 | `### N.M.K {标题}`，或第 3 段内 `### 判断标准一：…`、第 4 段内 `### 失败模式一：…` / `### 反面证据一：…` |
| 部扉 | `#` + 三个加粗导语 | 一部一页 | `# 第 N 部 · {部名}（第 x–y 章）`，下接「这一部管哪一段」「读完你能做什么」「章之间的依赖」 |

不要出现 `####`。不要用「本节小结」「本章小结」这类回扣标题——第 5 段就是交付，结尾不复述。

### 章末注

- **标题**：`## 本章注`
- **位置**：第 5 段之后、`## N.6 版本与复核` 之前。第 17 章的「尾声」仍在版本与复核之后，不动。
- **编号**：Markdown 脚注 `[^章-序号]`，如 `[^1-1]`、`[^6-12]`。章内从 1 连续编号。同一出处复用同一注号。
- **能不建就不建。** 一章若限定已写进叙述句、短名能解后记 C，可以没有本章注，不要空节，也不要为填节而回填定位符。
- **一条注只干一件事**，两种还允许的模板（定位符模板废止，路径走题注和表）：

```

```

## 章节模板

每章统一遵循的结构契约。参照手册五段纪律，按抽样现状把「章首怎么写、章末放什么」写死。部扉页、序、后记不适用本模板。

### 章首（第 1 段）

第 1 段必须让读者在一屏内知道三件事，但**用该章自己的句子**，不准套模板：

1. **本章讲什么**——该章特有的那句判断，不是「读完你能」。正例：「循环占 2% 到 10%。剩下的 90% 以上，就是本书要讲的东西。」「缓存按前缀匹配。前缀里任何一个字节变了，从那个字节往后的缓存全部作废。」「你对自己改动的修复效果有约 5 倍于随机的判断力，对回归效果只有约 2 倍。」
2. **为什么需要它、为什么是现在**——它在生命周期上卡住了后面哪些章。第 6 章「压缩、记忆、检索都要往上下文里写东西，先讲清这条铁律」是正例。
3. **要求读者已会什么**——有硬前置才写，写成具体回指（「读本章前建议先读第 1 章 §1.4」），不要写「读者应当具备 agent 基础知识」。

允许保留具体的故障后果清单，但直接陈述错误与结果。

禁止：段末朗诵「读完这一章，你能……」；把学习目标写成与部扉页重复的一段。

第 1 段不出现未解释的术语（手册硬性要求仍在）。必须说明不解决会怎样——可以是清单，也可以是嵌在判断里的一句。

### 第 2 段 · 各家怎么做

标题按内容拟定（「源码对照：……」「七层切分与……」）。每条论断在对照表或代码题注带路径（四种主证据不是源码的章除外）。至少覆盖 4 个项目。有对照表。

叙述句写机制与分歧，不写路径，不叠定位符注号。代码贴在页上是为了把机制讲清楚。对每一家问红线二的三句；能答「为什么 / 不这么做会怎样 / 抄不抄」的写在这家旁边，不要等到第 3、5 段才说。

### 第 3 段 · 判断标准

把选择写成可以回答是或否的条件，不能停在「视情况而定」。每条判断标准给出完整规则；图若用于表达条件之间的空间关系，放在本段，并用文字复述结论。

### 第 4 段 · 反面证据与失败模式

### 本章注

见版式规范。改稿分两步，不要混成一次语感润色——否则出处会在改写中丢失，机制也会被改回去：

1. **抽。** 叙述句里的定位符、书目全文、`[核 日期]` 拿走。路径已在题注或表里的，叙述句去掉对应上标，不要回填进本章注。测量方法、grep 口径进「版本与复核」。对照表和代码题注不动。
2. **补。** 对抽空的句子问三句。能补机制、代价、抄或不抄，就补。不能补，保持短。已经补上的，不要改回去。会改变用法的几个字（厂商自述、通用 agent、未复现、这是上界）写进叙述句，不要藏进注。
3. **扫味道。** 删「读完这一章」；自我拆台的括号改成后一句；删「口径见注」「可以自己去核」；能不标上标就不标。
4. **机器。** 跑扩展后的 `verify-citations.sh`。题注、对照表、验收清单里的路径必须仍全部可解析。

### 版本与复核（N.6）

维持两块，并承接从阅读主路径搬走的口径：

1. **本章基准**表，四行：素材复核日期、底稿、项目 commit、API / 外部来源基准。commit 写短哈希与日期。
2. **哪些会过期、怎么自己复核**：分类 + 保鲜期 + 可执行命令。命令默认在 `projects/` 下跑；未克隆指向后记 D.1。测量命令、grep 口径、推算链放这里——这是给要复跑的人，不是阅读主路径的喊话。

行内不再解释 `[核 …]` 记号（第 6 章基准块下那两行「行内标记约定」删掉，改由序在铺开时统一说明短名、本章注与基准块的分工）。
