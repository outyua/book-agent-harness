## 要做成什么样

读者顺着机制读完就能决定抄不抄。源码出现在页上，是把实现摊开讲；路径是题注（这段代码在哪），不是作业。

对照样章：

- 叙述句：项目名 + 机制 + 判断。需要时把代码贴出来，题注写路径。
- 会改变读法的几个字跟数字走，写在叙述句：「厂商自述」「本书推算」「这是上界，不是实测」「通用 agent 不是 coding agent」「未复现」「尚未通过同行评审」。
- 对照表单元格、代码题注、验收清单里的 `file:line` **原样保留**。
- 不要「口径见注」「可以自己去核」「要不要点进去核」「详见注」「可核」。
- 不要 `[核 YYYY-MM-DD]`、`[06-01 基准]` 出现在叙述句。
- 不要在叙述句里堆完整 `path/file.ext:123`、作者全名+题名+URL+arXiv、上标串。
- 不要建 `## 本章注`，除非有一条正文一句塞不下、又会改变用法的限定。样章最后是无本章注。
- 删「读完这一章，你能……」。章首用该章自己的判断。
- 抽出路径之后问三句，答得上写正文，答不上保持短：为什么这么做 / 不这么做会怎样 / 该抄哪段。禁止「由此可见 X 很重要」填空。
- 已经写好的机制判断不要改回去，不要把诚实限定写软。
- 五段结构、节号、基准块位置不要动。测量方法、grep 口径、推算链若从段中搬走，放进该章「版本与复核」，不要喊「口径见注」。

Claude Code：一章第一次出现时写「Claude Code（依据本仓库 source map 还原，快照 2026-06-01）」，后文只写「Claude Code」。

短名解后记 C，不要每次展开全题名。已有短名见 style sheet §5；本章新出现的论文/文章，首次给短名，后记已有条目的不要在正文抄书目字段。

表：内容表加 `**表 {章}-{序号}：{描述}**` 于表上方，正文用「见表 N-M」。不要「证据级别」盖章列，用法用表后一句人话。基准块表、保鲜期表不编号。图题统一 `图 N-M：` 带冒号。

力度按章：

- 第 2、3、4、5、7、8、9、10、11、14、15 章：叙述句去掉定位符，代码留在页上讲课。
- 第 12、13、16、17 章：书目短名化为主，上标能省则省。
- 序：把「带 file:line，可以自己去核」改成立足点是 23 个真实实现上的设计对照。后记 D / 各章「版本与复核」维持给要复跑的人，不要写进阅读主路径当卖点。诚实边界七条保留。
- 后记：C 的导语补一句「正文用短名，完整题名以本表为准」。D 怎么复核保持给要复跑的人。不要把后记改成认证手册。

## 操作顺序

1. 读指定稿件全文。
2. 抽：叙述句里的路径、书目全文、核日期、核查口吻拿走。表和代码题注不动。
3. 补：抽空后能答上三句的写机制；答不上保持短。
4. 扫：删模板句「读完这一章」；自我拆台的长括号改成后一句普通人话；无「口径见注」。
5. 表题、图题按 style sheet 补齐。
6. 不要整文件覆盖丢失未点名内容。用精确编辑。

完成后打印不超过 8 行：改了什么、删了哪些核验口吻、补了哪几处机制、有没有本章注、较大改动几处。
